# 알콜부시기 — 서면 3가게 콜라보

도쿄스탠드 서면점(맥주) · 조선칼국수와통막걸리 서면밀레오레본점(막걸리) · 와르르맨숀 서면점(소주). 세 집은 서로 50m 안에 있다.
**1차에서 마시고 계산할 때 휴대폰 번호를 말하면 쿠폰이 들어오고, 50m 안 다음 집에서 메인안주 1개를 주문할 때 보여 주면 그 집 특별 혜택을 받는다.**

이 사이트의 **주목적은 네이버 플레이스 트래픽**이다. 포스터 QR 은 플레이스로 가고, 플레이스 소개글의 링크가 이 사이트로 온다. 사이트는 손님을 다시 플레이스로 돌려보낸다.

| 사이트 | 주소 | 누가 |
|---|---|---|
| 손님 사이트 | `/` | 손님(휴대폰 기준). 홈 매장 카드 → 플레이스로 나가기, 쿠폰함에서 혜택 고르기 |
| 관리자 사이트 | `/admin` | 사장님·직원. 카운터(번호로 쿠폰 주기·사용 처리), 쿠폰 조회, 회원, 메뉴, 설정, 인쇄물, 직원 계정, 로그 |

## 어떻게 동작하나 (v7)

1. **카운터 발급.** 손님이 계산할 때 번호를 말하면 직원이 `/admin/counter` 에 번호를 넣고 [이 손님에게 쿠폰 주기]를 누른다. 처음 오는 번호면 그 자리에서 계정이 만들어진다. **영수증 사진·자동 인식·등급(VIP)은 쓰지 않는다.**
2. 손님은 `/wallet` 쿠폰함에서 50m 안 다른 두 집 중 한 곳의 혜택을 고른다. 쿠폰은 6자리 코드와 만료일을 가진다.
3. 다음 집에서 메인안주 1개를 주문하고 쿠폰 화면을 보여 주면, 직원이 카운터에서 번호로(또는 쿠폰 조회에서 코드로) 찾아 사용 처리한다.
4. **플레이스 깔때기.** 홈 매장 카드·매장 화면·플레이스 시트·이용 안내에 플레이스로 나가는 초록 버튼이 있다 — 예약하기, 리뷰 쓰기, 리뷰 보기, 메뉴 전체 보기, 사진, 길찾기, 저장, 네이버 검색으로 찾기. 주소는 `src/lib/naver.ts` 의 `placeLinks()` 한 곳에서만 만든다.
5. **다음 집 카드**가 1차 도쿄스탠드 → 2차 조선칼국수 → 3차 와르르맨숀 동선을 이어 준다.

### 관리자 → 설정에서 사장님이 바꾸는 값
- 쿠폰 유효 기간, 번호 하나당 하루 한도, 이벤트 진행 on/off, 손님 화면 상단 공지
- **매장 소식** — 매장마다 한 줄(80자). 손님 홈 매장 카드와 매장 화면에 보이고, 비우면 숨는다
- **리뷰 이벤트** — 매장마다 한 줄(40자). 손님 홈 '리뷰 쓰기' 줄과 이용 안내 FAQ 에 보인다

값은 `Rules`(`src/lib/config.ts`) → `saveRules`(`src/lib/settings.ts`) → DB `settings` 표로 저장되고, 저장하면 손님 화면에 바로 반영된다.

### 지키는 규칙
- 쿠폰을 받은 매장에서는 그 쿠폰을 쓸 수 없다(서버에서 강제). 같은 번호·같은 매장 하루 한도는 설정값을 따른다.
- 쿠폰 사용은 매장 직원이 처리한다. 손님 화면의 사용 완료에는 초 단위 시계가 돌아 스크린샷 재사용을 막는다.
- 로그인은 번호당 1시간 10회·IP당 10분 30회, 관리자 로그인은 IP당 10분 10회·계정당 15분 8회로 제한된다.

## 디자인 (v9 포스터 콜라주)

사장님 포스터(`public/images/event/poster.jpg`)가 화면 아래로 그대로 이어진다. 포스터의 밤거리 보케 한 장이 배경으로 고정되고, 그 위에 포스터에서 오려 낸 조각(간판·혜택·리본·순서·메모)이 기울어진 스티커로, 진짜 매장 사진은 폴라로이드로, 안내·쿠폰·입력은 크림색 종이로 붙는다. 글자는 제목·간판·버튼 Do Hyeon, 손글씨 메모 Nanum Pen Script, 본문 Pretendard — 앞의 두 글꼴은 `src/app/fonts.css` 에서 자체 호스팅한다. 버튼은 노란 스티커이고, **초록은 가게마다 네이버 예약하기 하나뿐**이다. 터치 44px, 가로 스크롤 없음. 규칙은 `docs/design.md` 2절.

**문구 톤(v10)**: 손님 화면의 글은 네이버 스마트플레이스·배달의민족·캐치테이블 같은 실제 매장 페이지처럼 쓴다 — 정보는 명사구 또는 합니다체(영업시간 · 주소 · 특별 혜택 · 이용 방법 · 자주 묻는 질문), 상태 칩은 영업 중 / 영업 전 · 17:00 오픈 / 영업 종료 / 휴무, 거리는 도보 1분, 혜택은 "다른 매장 쿠폰 제시 시 {품목} 무료", 버튼은 명사(예약하기 · 쿠폰함 · 사용하기 · 길찾기). 해요체·느낌표·이모지·"여기서/다른 집" 같은 잡담, 사진 캡션은 쓰지 않는다. 놀이 문구는 사장님 포스터 조각(이미지) 안에만 남긴다. 손글씨(Nanum Pen Script)는 크림 종이 위 6단어 이하 짧은 강조에만 쓰고, 영업시간·혜택·규칙·안내문 같은 정보 줄은 Pretendard 15~16px 로 종이나 어두운 띠(#14111a 85% 이상) 위에 놓는다. 보케 위에 바로 놓는 글자는 흰 Do Hyeon 20px 이상 + 검은 2px 외곽선(`.outl`)뿐이고, 노란 글자는 어두운 바탕에서만 쓴다. 문장은 칸 안에서 줄바꿈하고 `nowrap` 으로 잘라내지 않는다.

**이미지 키트(`public/images/kit/`)**: 디자이너가 만드는 포스터풍 그림 55장(+먼저 받은 8장)은 파일 이름으로 자리가 정해져 있어, 파일을 이 폴더에 넣고 `npm run kit`(등록부 `src/lib/kit-manifest.json` 갱신 + 앱 아이콘 `src/app/icon.png`·`apple-icon.png` 생성)을 돌리면 코드 수정 없이 화면이 바뀐다. 파일이 없으면 지금의 포스터 조각·CSS 로 그린다. 먼저 받은 8장은 이렇게 쓴다 — `ticket-<매장>.png` 는 쿠폰 화면과 쿠폰함의 네온 쿠폰(`src/components/flow/NeonTicket.tsx`; 55장의 크림 `ticket.png` 가 오면 종이 쿠폰이 그 그림 위에 그려지며 우선한다 — `Ticket.tsx`), `empty-wallet.png` 는 빈 쿠폰함, `notfound.png` 는 404·오류 화면, `icon.png` 는 앱 아이콘(`icon.svg` 는 같은 표시를 벡터로), `share.jpg` 는 카톡·네이버·트위터 공유 미리보기(포스터가 두 번째), `sign-wareureu.png` 는 3차 와르르맨숀 아래 장식 선. 버튼(`btn-*`)·섹션 제목(`label-*`)·탭 아이콘(`icon-*`)은 `src/components/site/Kit.tsx` 의 `<StickerButton>`·`<SectionLabel>`·`<TabIcon>` 이 키트 유무에 따라 그림과 CSS 를 고른다. 파일 목록과 자리는 `docs/kit.md`.

알아 둘 것: Vercel Hobby(무료)는 약관상 비상업용이라 매장 홍보용으로 계속 쓰려면 Pro(월 $20)로 올려야 한다. Neon Free 는 0.5 GB·월 100 컴퓨트시간이라 이 규모에는 충분하고, 5분 쉬면 잠들었다가 첫 요청에 1~2초 걸려 깨어난다.

## 직접 배포 (Vercel + Supabase, 30분)

1. **Supabase** 프로젝트 생성(Region: Northeast Asia/Seoul) → Project Settings → Database → *Connection string* 의 **Transaction pooler**(포트 6543) 주소를 복사. 비밀번호를 넣어 `DATABASE_URL` 로 쓴다. 스키마는 앱이 첫 요청에서 자동 생성한다(미리 만들려면 SQL Editor 에서 `supabase/schema.sql` 실행).
2. **Vercel** → New Project → 이 저장소 → Framework: Next.js. Environment Variables 에 `.env.example` 의 값을 모두 넣는다. `SESSION_SECRET` 은 `openssl rand -base64 48`, `CRON_SECRET` 은 `openssl rand -hex 24`. `NEXT_PUBLIC_SITE_URL` 은 실제 도메인(포스터 QR 에 들어간다 — 배포 주소가 아니면 포스터 위에 빨간 경고가 인쇄된다). Supabase 의 SSL certificate 를 `DATABASE_CA` 에 넣으면 DB 연결의 서버 인증서를 검증한다. Deploy. `vercel.json` 의 크론이 매일 03:00(KST) `/api/cron/purge` 를 불러 오래된 속도 제한 행을 지운다.
3. 배포 후 `/admin/login` 에 `ADMIN_INITIAL_ID`/`ADMIN_INITIAL_PASSWORD` 로 들어가 **비밀번호부터 바꾸고**, 매장별 직원 계정을 만든다.
4. 관리자 → 메뉴에서 **혜택 품목**(기본은 막걸리·생맥주·소주)을 확정(토글)하고 사진을 올린다. 설정에서 쿠폰 유효일·하루 한도·매장 소식·리뷰 이벤트를 채운다.
5. 관리자 → 포스터에서 매장별 A4 포스터를 인쇄해 붙인다(QR 두 개: 사이트, 네이버 플레이스).

관리자 사이트를 별도 도메인(예: `staff.도메인`)으로 쓰고 싶으면 Vercel 에 도메인을 추가하고 `src/proxy.ts` 에서 호스트가 그 도메인이면 `/admin` 으로 rewrite 하면 된다.

Vercel 은 새 저장소를 그대로 연결하면 된다(Root Directory 기본값).

## 테이블톡 (/t/…) — 같은 가게 테이블끼리 단체 대화

테이블에 붙인 QR 을 찍으면 로그인 없이 들어가서, 같은 가게 다른 테이블에 말을 걸고 테이블 대 테이블로 대화한다.
쿠폰·로그인과는 따로 돈다. 코드는 `src/lib/tabletalk/`(서버) · `src/components/tabletalk/`(화면) · `src/app/api/tt/route.ts`(API 하나).

**손님 흐름**
1. 테이블 QR → [테이블톡 시작]. 그 테이블에 처음 들어온 폰이 "자리"를 연다.
2. 같이 온 일행은 같은 QR 을 찍으면 같은 테이블로 들어온다. 자리가 열리고 5분 안에 찍으면 바로,
   그 뒤에 오는 폰은 먼저 들어간 폰이 **[허락]** 해야 들어온다 — 지나가다 남의 테이블 QR 을 찍은 사람이
   그 테이블 행세를 하거나 대화를 엿보지 못하게.
3. 번호판(테이블에 붙은 번호 그대로)에서 불 들어온 번호를 눌러 말을 건다(첫 마디는 선택). 상대 테이블 폰 중 하나가 **[수락]**하면
   두 테이블의 대화방이 열리고, 양쪽 테이블 폰 모두가 같이 본다. 서로 신청하면 바로 열린다.
   거절·취소한 신청은 15분 동안 같은 테이블에 다시 걸 수 없다(취소하고 다시 걸며 첫 마디로 괴롭히지 못하게).
4. 대화방 메뉴: 나가기(15분 뒤 다시 걸 수 있음) · 차단(오늘 밤 서로 못 검) · 신고(차단 + 직원에게 대화가 감).
   받은 신청 카드의 [차단·신고]로 방이 열리기 전에도 막을 수 있다(신고면 첫 마디가 직원에게 감).
   상대에게는 "대화가 끝났습니다"로만 보이고 누가 막았는지는 알리지 않는다.
   차단은 막힌 쪽 **테이블 번호**에 걸린다 — 막힌 손님이 [자리 떠나기] 뒤 다시 찍어도 막혀 있다.
   직원이 그 테이블을 비우거나, 새 일행이 [방금 이 자리에 앉았습니다]로 앉으면 다른 손님이라 풀린다.
5. 나갈 때 [나가기 → 자리 떠나기]. 상대 방에는 "자리를 떠났습니다"가 남는다.

**자리가 끝나는 때** — 자리 떠나기 · 직원이 비우기 · 3시간 동안 아무 폰도 안 봄 · 영업일이 바뀜(한국 낮 12시, 세 가게가 모두 닫혀 있는 시간).
새 손님이 이전 손님 자리가 남은 테이블에 앉으면 [방금 이 자리에 앉았습니다]로 새로 시작할 수 있다(이전 손님 폰이 20분 넘게 안 봤을 때만 —
폰을 주머니에 넣고 마시는 일행을 테이블 주소를 가진 다른 사람이 밀어내지 못하게).
사장님이 그 가게 테이블톡을 끄면 들어와 있던 폰도 30초 안에 닫힌다.
그 전이면 직원이 관리자 → 테이블톡에서 [비우기].

**직원(관리자 → 테이블톡)** — 지금 켜진 테이블·폰 수·대화 상대, [비우기], [오늘 막기/풀기], 신고(오간 글 40줄까지) 처리.
총괄은 매장별 켜기/끄기·테이블 수·[QR 새로 만들기](QR 사진이 밖으로 퍼졌을 때 — 예전 QR 은 안 열림)와 사용량을 본다.
신고가 있으면 내비 [테이블톡] 옆에 숫자가 뜬다. 인쇄물 → **테이블톡 QR** 에서 A4 한 장에 8장씩 뽑아 테이블 번호대로 붙인다.

**QR 주소** — `/t/{매장}-{번호}-{서명6자}`. 서명은 `SESSION_SECRET` HMAC 이라 한 테이블 QR 로 다른 테이블 주소를 만들 수 없다.
`SESSION_SECRET` 을 바꾸면 인쇄한 QR 이 모두 무효가 된다.

**실시간 방식과 무료 요금제** — 화면이 몇 초마다 묻는다(대화방 2.5초, 번호판 4초, 조용하면 최대 20초, 화면이 꺼져 있으면 안 물음).
자리마다 변경 번호가 있어 그대로면 서버는 DB 한 줄만 읽고 끝낸다 — 다른 테이블끼리 대화해도 우리 자리 번호는 안 바뀐다.
쓰기는 매장마다 한 줄로 서서(tt_state 줄 잠금) 동시에 눌러도 엇갈리지 않고, 글이 커밋된 순서대로 번호가 붙어 빠지는 글이 없다. Vercel Hobby 는 한 달 요청 100만 번을 넘으면 사이트 전체가 30일 멈추므로,
최근 30일 테이블톡 요청을 세어 예산(기본 45만, `TT_BUDGET`)의 40%를 넘으면 서버가 묻는 간격을 늘리고, 95%면 새 글·새 신청만 멈춘다
(새로 들어오기·수락도 멈춘다. 사이트와 보던 대화는 그대로). 관리자 → 테이블톡 아래에 사용량이 보인다. 손님이 많아져 자주 느려지면 Vercel Pro 로 올리는 게 맞다.

**보관** — 대화는 영업일이 지나면(다음날 낮 12시) 닫히고, 매일 새벽 크론(`/api/cron/purge`)이 이틀 안에 지운다. 신고(복사해 둔 글)는 14일. 이름·전화번호는 받지 않는다.

확인: `PGLITE_MEMORY=1 npx tsx scripts/smoke-tabletalk.ts` (여러 폰 시나리오를 실제 SQL 로).

## 운영 주의
- **전화번호만으로 로그인**하므로(인증번호 없음 — 사장님 결정) 남의 번호를 아는 사람이 그 번호로 들어와 쿠폰함을 보고, 길게 눌러 쿠폰을 "사용" 처리해 버릴 수 있다. 완화책: 번호당 로그인 1시간 10회·IP당 10분 30회 제한, 쿠폰 사용은 매장 직원 앞에서만 인정(직원은 관리자 → 쿠폰 조회에서 코드로 확인하고 사용 처리하는 것을 기본 동선으로), 분쟁이 잦으면 SMS 인증(알리고·솔라피 등)을 `/api/auth/login` 앞에 붙인다.
- **손님은 사진을 올리지 않는다.** 쿠폰은 카운터에서만 나온다. 영수증 업로드·자동 인식·등급(VIP) 코드는 저장소에 남아 있지만 어느 화면에서도 쓰지 않는다.
- **관리자 초기 계정**: 운영에서는 `ADMIN_INITIAL_PASSWORD` 를 반드시 10자 이상의 새 값으로(`Seomyeon2026owner` 처럼). `admin1234` 같은 흔한 값이면 총괄 계정을 만들지 않고 `/admin/login` 에 그 이유를 띄운다 — 손님 사이트는 그대로 열린다. 배포 후 첫 로그인에서 직원 계정을 만들고, 총괄 비밀번호는 `scripts/create-admin.ts` 로 바꿀 수 있다. 관리자 로그인은 IP당 10분 10회, 계정당 15분 8회로 제한된다.
- **직원(staff) 계정**은 카운터에서 자기 매장만 다룰 수 있고 매장을 바꿀 수 없다. 설정·직원·메뉴는 총괄(owner)만 연다.
- **QR 입구 `/q/{매장}`** (`/q/tokyo`, `/q/joseon`, `/q/wareureu`): 찍으면 그 가게 플레이스가 바로 열린다. 사이트로 오는 QR 은 이 주소로 만들고, 스마트플레이스의 홈페이지 칸에 사이트 주소를 넣어 두면 손님이 플레이스 → 사이트로 온다.
- 네이버 플레이스 연동은 링크·QR(트래픽 유도)이다. 네이버가 외부 사이트에 방문 데이터를 주지 않으므로, 플레이스로 몇 명이 넘어갔는지는 사이트에서 셀 수 없다. 방문 인정은 카운터에서만 한다.
- 관리자 → 포스터는 매장에 붙이는 인쇄물이다(손님 사이트에는 QR 이 없다). `NEXT_PUBLIC_SITE_URL` 이 배포 주소가 아니면 시트 위에 경고가 인쇄되고 인쇄 버튼이 한 번 더 묻는다.
